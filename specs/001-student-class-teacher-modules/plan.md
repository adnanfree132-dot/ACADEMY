## Summary

This implementation plan delivers the technical blueprint for the core academic entities in Academy Pro OS: **Student Management (`M2 STU`)**, **Academic Classes & Batches (`M5 ACA`)**, and **Teacher & Faculty Management (`M4 TCH`)**. 

The architecture implements complete full-stack vertical slices connecting React 18 / Vite UI views ([StudentsView](file:///d:/academy/src/pages/StudentsView.tsx), [BatchesView](file:///d:/academy/src/pages/BatchesView.tsx), [TeachersView](file:///d:/academy/src/pages/TeachersView.tsx)) via typed [apiClient.ts](file:///d:/academy/src/api/apiClient.ts) methods to Express 4 REST routes ([routes.ts](file:///d:/academy/server/src/routes.ts)) with Zod validation, and Prisma Client ORM interacting with PostgreSQL. All UI components strictly adhere to Constitution v1.1.0 Taste Standards (curated palettes, glassmorphism, 12px+ radii, and explicit action labeling).

---

## Technical Context

**Language/Version**: TypeScript 5.x, Node.js 20.x, React 18.2  
**Primary Dependencies**: Express 4.21, Prisma Client 5.22, Zod 3.24, bcrypt 5.1, jsonwebtoken 9.0, Lucide React 0.344, Vite 5.4  
**Storage**: PostgreSQL 16 (Local Docker in Phase 1; Supabase PostgreSQL in Phase 2 with identical Prisma schema)  
**Testing**: Playwright automated E2E suites (`test_e2e_full_flow.cjs`, `test_all_buttons.cjs`), TypeScript type checking (`tsc --noEmit`)  
**Target Platform**: Web Application (Desktop and Tablet viewports >= 768px)  
**Project Type**: Full-Stack Web Application (React SPA + Express REST API)  
**Performance Goals**: Directory searches across 1,000+ records < 100ms; Student registration flow completion < 60s; Bulk CSV import of 100 records < 5s  
**Constraints**: Zero hard deletes on financial/attendance/student history; strict batch capacity enforcement with admin override; all state modifications recorded in `audit_logs`  
**Scale/Scope**: 3 core modules (`M2 STU`, `M5 ACA`, `M4 TCH`), 24 functional requirements, 7 database entities
